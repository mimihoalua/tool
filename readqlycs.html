7 Quy tắc Vàng (Tuyệt đối không vi phạm)

Bất kỳ ai chạm vào mã nguồn V29 đều phải thuộc lòng 7 nguyên tắc sống còn sau đây. Đây là kết quả của hàng chục giờ debug các lỗi chết ngầm nguy hiểm nhất.

1 Pháo Đài Offline (Chống ORB/404)

Bài học: CDN dễ bị chặn bởi Tường lửa hoặc Playwright (Lỗi ORB). Đường dẫn tương đối ./ trên GitHub Pages gây lỗi tải nhầm trang 404 HTML thành file JS, gây crash Unexpected token '<' làm sập toàn bộ Firebase.

Quy định bắt buộc:

  • 4 file cốt lõi (jsOTP, firebase-app, -auth, -firestore) phải nằm cùng cấp với HTML.
  • Phải dùng đường dẫn tuyệt đối /tool/filename.js.

2 Thanh trừng "Undefined" (Chống Crash Firebase)

Bài học: Firestore sẽ lập tức ném lỗi Unsupported field value: undefined và từ chối lưu dữ liệu nếu có bất kỳ thuộc tính nào mang giá trị undefined. Bắt buộc phải chạy vòng lặp delete cleanT[key] để tẩy rửa toàn bộ object trước khi gọi this._d.collection(...).set().

3 Cấm Push Lúc Khởi Động (Anti-Race Condition)

Bài học: Tuyệt đối KHÔNG ĐƯỢC gọi this.pushAll() trong hàm init(). Nếu gọi, thiết bị vừa mở lên sẽ lập tức lấy dữ liệu cũ của nó đè bẹp dữ liệu mới trên Cloud mà thiết bị khác vừa đẩy lên, gây mất dữ liệu vĩnh viễn.

4 Đồng Hồ Vector & Ép Kiểu toMillis()

Bài học: Xóa bỏ hoàn toàn cờ `cloudSyncCompleted`. Giải quyết tranh chấp dựa 100% vào thời gian. Firebase trả về Object Timestamp, bắt buộc phải dùng c.updatedAt.toMillis() để ép về số nguyên (Integer) mới có thể so sánh cloudTime > localTime chính xác.

5 Kén Âm Thanh 3 Ống Tủy & Web Worker

Duy trì cụm 3 thẻ Audio: mstq-silence (giữ mạng), mstq-alarm (chuông vật lý), và tts-audio (ép luồng Google Translate). Kết hợp Web Worker để đếm giờ ngầm xuyên qua chế độ ngủ (Doze Mode) của màn hình điện thoại.

6 Ép kiểu ID thành Chuỗi (String Casting)

Luôn bọc String(t.id) khi tìm kiếm hoặc map mảng dữ liệu để tránh lỗi Javascript không so sánh được ID dạng Number (từ Local) và String (từ Firebase).

7 Tránh Tử Huyệt Visibility Deadlock

Chỉ dùng document.visibilityState === 'hidden' cho vòng lặp Audio. Tuyệt đối không chặn hàm renderTasksOnly() khi nhận Data từ Firebase, nếu không Tab chạy ngầm sẽ bị "mù" dữ liệu vĩnh viễn.

2. Cấu trúc Lưu trữ (Storage Flow)

Mỗi hồ sơ sở hữu 4 Key độc lập trong LocalStorage. Dữ liệu trên Cloud lưu theo document LifeOS_Profiles/[tên-đăng-nhập].

Tên Key (LocalStorage / Field) Mô tả cấu trúc
lifeos_v8_data_[tên] Mảng todos / Mảng data trên Cloud (Nhiệm vụ). Đã được bọc bộ lọc tẩy rửa `undefined` trước khi đẩy lên Cloud.
lifeos_stats_v8_[tên] Object stats (Đếm Ngọn lửa Chuỗi kỷ luật).
lifeos_v8_time_[tên] Lưu lại Timestamp (Integer) cập nhật CÙNG LÚC khi thao tác, làm đối trọng so sánh với Timestamp.toMillis() của Firebase.
lifeos_v8_vault_[tên] Mảng VaultState.data / Field vaultData trên Cloud (Kho lưu trữ, 2FA, Password).

3. Đồng bộ Vector Clock (Không Race Condition)

Chủ Động Đẩy (Push Flow)

  • 1 Người dùng thao tác (Tạo/Sửa/Xóa Task).
  • 2
    Hệ thống lấy Date.now() lưu vào LocalStorage và mảng dữ liệu.
  • 3
    Bộ lọc tẩy sạch `undefined`. Ném mảng dữ liệu và Timestamp đó lên Firebase. Chấm dứt việc tự động ném dữ liệu lúc khởi động app.

Chủ Động Kéo (Pull Flow)

  • 1 Firebase báo onSnapshot có dữ liệu mới.
  • 2 Ép kiểu cloudTime = toMillis(). Lấy localTime.
  • 3
    So sánh: Nếu cloudTime > localTime -> Cập nhật DOM. Nếu localTime > cloudTime (Firebase trả chậm) -> Bỏ qua snapshot cũ, ném ngược Local lên Cloud!
